# Connect an external AI assistant

SSH Heaven provides an optional local MCP server for clients such as Claude Desktop and Codex. It does not contain an AI chat, call a model API, or require an AI API key of its own. Your chosen assistant supplies the model.

## Setup

1. Open SSH Heaven and connect the SSH sessions you want the assistant to inspect.
2. Open **MCP server** in the sidebar and choose **Enable server**.
3. Copy the generated **Claude JSON** or **Codex TOML** configuration into your client's MCP settings. The configuration uses the installed application's runtime and a standalone bridge; no separate Node.js installation is needed.
4. Restart or reconnect the client's MCP connection and ask it to list SSH Heaven's tools and connected sessions.

The Codex snippet uses a `[mcp_servers.ssh-heaven]` entry with a command, arguments, environment, and an extended tool timeout to allow time for user review. Claude's snippet uses the `mcpServers` JSON format. Use the exact configuration generated by your installed copy so paths match its installation.

SSH Heaven must stay open. MCP starts disabled each time the app starts. After disabling and re-enabling it, reconnect or restart the client's MCP connection so its bridge reads the new local connection details.

## Access and approvals

Read-only tools expose saved host metadata, connected session metadata, Linux server metrics, remote directory listings, and supported remote text files. Stored passwords and local private-key contents are not exposed. Session tools use SSH connections already open in SSH Heaven.

Commands and file changes stop at an in-app **Review AI request** dialog. Review the exact server and port, command or file path, and current/proposed file contents, then approve or deny that individual request. Group commands show a fixed list of connected targets. Pending requests expire, and disabling MCP cancels pending work. Cancellation closes execution channels; remote processes already launched may continue.

The app checks that the SSH connection is still the same one reviewed before an approved mutation starts. Remote file writes also use the editor's content-version checks and temporary-file save behavior. MCP edits require both versions to be at most 64 KiB so the entire proposed change can be shown for review; use the built-in editor for larger files. Reads support regular UTF-8 files up to 2 MiB. The server blocks recognized SSH private-key material from tool results and edits.

The listener binds only to `127.0.0.1`, requires a random authentication token, and validates HTTP Host and Origin headers. Client configuration snippets contain a bridge command and connection-file path rather than the token. The local connection file is restricted to the current account; disabling the server removes it. No settings are written to another assistant automatically.

## Troubleshooting

- **No tools:** enable MCP in the open app, then reconnect the client's MCP server. Recopy the configuration if the app was moved or reinstalled in a different directory.
- **No connected sessions:** connect a host in SSH Heaven first. Saved host inventory is available independently of a live session.
- **Request timed out:** bring SSH Heaven forward and review the pending request before it expires. Use the generated timeout settings.
- **Connection changed:** the SSH session reconnected or disconnected during review. Ask the assistant to make a fresh request against the current session.
- **File conflict:** the remote file changed since it was read. Read the current version again and review a new edit.
